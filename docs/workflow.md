# CodeFlow 操作与故障排查

启动入口为 `python workflow.py --open`，默认端口 8010。`webui.py` 是基础代码助手的独立界面。

## 推荐体验顺序

1. 配置 `.env` 并重启，页面应显示 DeepSeek 已配置。
2. 点击“修复空列表求平均值”，查看输入需求和代码，再点击开始。
3. 在生成期间查看节点卡片、计划预览和当前进度。
4. 在代码交付中切换实现 / 测试文件，查看差异、审查清单与日志。
5. 下载 ZIP 后先检查代码，再运行生成的测试。

无密钥时选择“载入离线演示”，不要用离线模式处理自定义任务。离线固定案例会故意产生有问题的首稿，以明确展示修复分支；页面和导出都标明演示来源。

## 恢复任务

- 刷新网页：重新连接服务端状态；正在执行的任务会继续。
- 暂停：当前请求结束后保存结果，然后暂停后续节点。
- 重启服务：原运行记录变为暂停，打开历史记录后点击继续。
- 失败：先检查错误信息，再重试当前缺失节点，已有成功结果不会重复请求。
- 迁移：从旧服务导出 JSON，再在新服务的历史弹窗导入。导入不自动执行。

## 常见问题

| 情况 | 处理 |
| --- | --- |
| 找不到 Python | 安装 Python 3.10+ 并加入 PATH；Windows 可尝试 `py -3 workflow.py --open` |
| 端口被占用 | 用 `--port 8011` 指定新端口 |
| 已配置但认证失败 | 检查 `.env`、账户与接口地址，修改后重启；“已配置”不代表额度或实时可用性 |
| 余额不足 / 限流 | 检查自己的 DeepSeek 账户，等待后手动恢复 |
| JSON 合同失败 / 输出截断 | 缩小任务范围，保留成功规划后重试；复杂多文件任务超出当前 MVP 范围 |
| 已有任务正在执行 | 通过历史记录打开运行中任务，等待或暂停后再新建 |
| 重启后看不到历史 | 确认启动的是同一项目副本，记录保存在该副本的 `.workflow_runs/` |
| 存储失败 | 检查磁盘和目录权限，及时导出可读取的运行记录 |

模型请求最多等待 120 秒。工作流节点内可调用只读静态工具，可能产生多次模型请求；工作台记录实际请求数。
